# 달력과 모두의 시간 설계

- 작성일: 2026-09-30
- 상태: 구현 완료(계획 3·4). 실제 Neon·Vercel·폰에서의 확인은 남아 있다.
- 관련 스펙: `2026-09-30-docs-backoffice-design.md` (문서 뷰어, 알림, 일정). 이 문서는 그 스펙의 **일정 기능(5.6~5.8, 6.4)을 달력 화면으로 확장**하고, **모두의 시간(시간 조율)을 새로 더한다.** 겹치는 부분은 이 문서가 우선한다.

## 1. 목적과 성공 기준

**목적.** 고정된 5명의 팀이 (1) 사이트 안의 달력에서 일정을 보고 직접 추가·수정·삭제하고, (2) '모두의 시간'처럼 각자 가능한 시간을 표시해서 모두가 되는 시간대를 찾고, 확정하면 그 시간이 달력에 일정으로 들어가게 한다. 모임이 열리거나 확정될 때, 그리고 일정 전날·당일에 폰으로 알림이 간다.

**사용자와 조건.**
- 참가자는 고정된 5명이다. 지금은 임의로 번호(`참가자 1~5`)를 쓰고, 나중에 실제 이름으로 바꾼다. 로그인과 개인 비밀번호는 없다.
- 쓰기 보호는 기존 방침대로 팀 공용 편집 코드다.
- 무료 플랜(Vercel Hobby, Neon Free) 한도 안에서 운영한다. Hobby의 cron은 하루 1회라서 시각 단위 알림은 만들지 않는다.

**성공 기준.**
1. 월 달력에서 일정을 보고, 날짜를 눌러 일정을 추가·수정·삭제할 수 있다. 일정에는 시각(시작~종료)이 선택 사항이다.
2. 모임을 만들고 5명이 각자 가능한 시간을 표시하면, 겹치는 시간이 히트맵과 추천 목록(Top 3)으로 보인다.
3. 편집 코드로 시간을 확정하면 달력에 일정이 생기고, 그 시간에 전부 가능한 사람이 참석자로 들어간다.
4. 모임이 열릴 때와 확정될 때 폰 알림이 가고, 일정은 전날·당일에 알림이 간다. 같은 알림이 두 번 가지 않는다.
5. 편집 코드 없이는 모임 만들기·삭제·확정과 일정 추가·수정·삭제를 할 수 없다.

## 2. 범위

**포함.** 5명 명단 설정, 월 달력, 일정 CRUD(시각 선택), 모임 만들기, 가능한 시간 표시, 겹치는 시간 계산과 추천, 확정 → 일정, 참석자 표시, 모임 알림, 일정 전날·당일 알림.

**제외 (YAGNI).** 로그인, 개인 PIN, 구글 등 외부 달력 연동과 동기화, 주간·일간 보기, 드래그로 일정 옮기기, 반복 일정, 시각 단위 알림(예: 30분 전), 요일 기준 주간 시간표, 모임별 참가자 지정(항상 5명 전원), 사람과 알림 기기의 연결.

## 3. 결정 기록

| 결정 | 선택 | 이유 |
|---|---|---|
| 참가자 구분 | 고정 5명 명단에서 이름 선택 | 사용자 선택. 로그인·PIN 없이 가장 단순 |
| 명단 저장 | 환경변수 `PEOPLE`(번호:이름). 데이터는 번호만 참조 | 이름을 바꿔도 기록이 유지된다 |
| 조율 단위 | 날짜를 정하는 모임(후보 날짜 + 시간대) | 사용자 선택 (when2meet 방식) |
| 달력 | 사이트 안의 직접 만든 월 달력 | 사용자 선택. 외부 달력 연동은 하지 않음 |
| 구현 방식 | 하나의 앱에 통합, Neon 하나에 저장, 라이브러리 없이 월 달력 | 5명 규모에 충분하고 폰 화면에 맞추기 쉽다 |
| 쓰기 권한 | 편집 코드: 모임 만들기·삭제·확정, 일정 CRUD. 코드 없음: 가능한 시간 저장 | 스팸 방지와 참여 편의의 균형 |
| 첫 버전에 함께 넣음 | 참석 가능한 사람 표시, 모임 열림·확정 알림, 일정 전날·당일 알림 | 사용자 선택 |

## 4. 구현 순서와 의존

1. **계획 2:** PWA와 푸시 알림(Neon 연결, 구독 저장, Web Push. 문서 갱신 알림은 사용자 결정으로 뺐다). 이 문서의 알림 기능이 모두 이것 위에 올라간다.
2. **계획 3(확장):** 달력과 일정. 월 달력, 일정 CRUD, 편집 코드, 하루 단위 cron 알림, 5명 명단.
3. **계획 4(신규):** 모두의 시간. 모임, 가능 시간, 겹침 계산, 확정 → 일정, 모임 알림.

**배포 순서.** 폰 푸시(특히 iPhone의 홈 화면 웹앱)는 HTTPS 주소에서만 확인할 수 있으므로, Vercel 배포는 문서 뷰어 단계에서 먼저 하고 **팀 저장소를 건드리는 webhook 등록은 모든 기능 뒤**로 미룬다.

## 5. 데이터 (Neon Postgres)

시간대는 모두 한국시간(시간대 없는 날짜와 시각)으로 다룬다. 계획 3은 `events`를 `meetup_id` 없이 만들고, 계획 4의 마이그레이션이 `meetups`를 만든 뒤 `events.meetup_id`를 더한다.

```
events(
  id, title, event_date date, start_time time null, end_time time null,
  memo null, attendee_ids text[] default '{}', remind_offsets int[] default '{0,1}',
  meetup_id null → meetups(id) on delete set null, created_at, updated_at)
meetups(
  id, title, status 'open' | 'confirmed', dates date[] (정렬, 최대 14개),
  day_start time, day_end time, slot_minutes int = 30, created_at, confirmed_at null)
availability(
  meetup_id → meetups(id) on delete cascade, person_id text, day date, slot smallint,
  PK (meetup_id, person_id, day, slot))            -- "가능"한 칸만 저장
sent_notices(kind text, ref_id, sent_at, PK (kind, ref_id))   -- 'meetup-opened' | 'meetup-confirmed'
+ 계획 2와 기존 스펙의 push_subscriptions, sent_reminders, auth_attempts
```

- **칸 번호:** `slot 0`이 `day_start`이고 `slot_minutes`씩 커진다. 하루 09:00~22:00, 30분 단위면 칸이 26개다.
- **저장:** 한 사람이 저장하면 그 모임에서 그 사람의 칸을 통째로 바꾼다(다른 사람 데이터는 그대로). 나중 저장이 이긴다.
- **명단:** `PEOPLE="p1:참가자 1,p2:참가자 2,p3:참가자 3,p4:참가자 4,p5:참가자 5"`. 저장된 `person_id`, `attendee_ids`는 `p1` 같은 번호만 쓴다. 명단에 없는 번호는 거부한다.

## 6. 화면

헤더: `문서 | 달력 | 모임 | 🔔`

### 6.1 달력 (`/calendar?month=YYYY-MM`)
- 일요일 시작 월 달력이다. 위에 `‹ 2026년 10월 ›`와 `오늘` 버튼이 있다.
- 날짜 칸에는 일정 제목을 최대 2개 보여주고 더 있으면 `+N`으로 줄인다. 모임에서 확정된 일정은 색을 달리한다.
- 날짜를 누르면 그날 일정 목록과 "일정 추가"(편집 코드 필요)가 열린다. 일정을 누르면 제목, 시간, 메모, 참석자와 수정·삭제가 보인다.
- 일정 폼: 제목(1~100자), 날짜, 종일 또는 시작~종료 시각(종료가 시작보다 뒤), 메모(500자 이하), 참석자(5명 체크, 선택), 알림 시점(당일, 1일 전, 3일 전).
- 편집 코드를 입력하지 않았으면 추가·수정·삭제 시점에 코드 입력창이 뜬다(스펙 5.8과 같은 서명 쿠키와 잠금).

### 6.2 모임 목록 (`/meetups`)
- 열린 모임과 확정된 모임을 나눠서 보여준다.
- "새 모임"(편집 코드 필요): 제목(1~100자), 후보 날짜(시작~끝, 최대 14일), 하루 시작·끝 시각(기본 09:00~22:00, 30분 단위, 시작이 끝보다 앞).

### 6.3 모임 상세 (`/meetups/[id]`), 탭 두 개
- **내 시간:** 위에서 내 이름을 5명 칩 중에 고른다(마지막으로 고른 이름은 이 기기에 기억한다). 열은 날짜, 행은 30분 칸인 표에서 가능한 칸을 표시하고 "저장"한다.
  - 마우스는 드래그로 칠할 수 있고, 터치는 스크롤과 겹치지 않도록 탭으로 켜고 끈다.
  - 날짜 머리글을 누르면 그날 전체를 선택한다.
  - 확정된 모임은 읽기 전용이다.
- **전체 결과:** 같은 표가 히트맵이다. 가능한 사람이 많을수록 진하고, 칸을 누르면 가능한 사람 이름이 보인다. 아래에 **추천 시간 Top 3**(예: "10/7(수) 14:00–16:00 · 5명 모두 가능")과 "확정" 버튼(편집 코드 필요)이 있다.
- **확정 창:** 추천 중에서 고르거나 날짜와 시작·끝을 직접 입력한다. 알림 시점을 고르고 확정하면 일정이 만들어진다.

## 7. 규칙

### 7.1 겹치는 시간 계산 (`lib/meetups/overlap`, 순수 함수)
- 입력: 모임(날짜, 하루 범위, 칸 크기), 사람별 가능한 칸, 명단. 출력: 칸별 가능한 사람 수와 번호, 추천 구간 목록.
- **추천 규칙:** 최소 2칸(1시간) 이상 연속인 구간만 후보다. 그 구간 **전체에서 가능한 사람**의 수로 순위를 매긴다. 전원이 가능한 구간이 있으면 먼저, 없으면 가능한 사람이 가장 많은 구간이다. 같으면 더 긴 구간, 그다음 더 이른 시각 순이다. 더 늘려도 인원이 줄지 않는 한 구간은 늘려서 하나로 합치고(극대 구간), 최대 3개를 추천한다. 가능한 사람이 한 명도 없으면 추천은 비어 있다.

### 7.2 확정 (`lib/meetups/confirm`)
- 한 트랜잭션에서 `meetups.status = 'confirmed'`로 바꾸고 `events`에 일정을 만든다. 일정의 참석자는 **확정 구간 전체에서 가능한 사람**이고, `meetup_id`로 모임과 연결된다.
- 이미 확정된 모임, 이미 삭제된 모임, 명단 밖의 사람, 후보 날짜 밖의 날짜나 하루 범위 밖의 시각은 거부하고 이유를 알려준다.

### 7.3 권한 (`lib/auth`, 기존 스펙 5.8과 동일한 서명 쿠키와 잠금)
- 편집 코드가 필요한 동작: 모임 만들기·삭제·확정, 일정 추가·수정·삭제.
- 코드가 필요 없는 동작: 조회, 알림 구독, 가능한 시간 저장(이름 선택만). 남의 이름으로도 고칠 수 있지만 5명 팀이라 수용한다.

### 7.4 알림 (`lib/push` 공용 모듈 사용)
- **모임 열림:** "새 모임: {제목} — 가능한 시간을 표시해 주세요"(열 주소 `/meetups/{id}`). **모임 확정:** "{제목} 확정: 10/7(수) 14:00–16:00"(열 주소 `/calendar?month=2026-10`). 두 알림은 `sent_notices`로 모임당 한 번만 보낸다.
- **일정 전날·당일:** 스펙 5.7의 cron(하루 1회, 한국시간 09:00~09:59경)을 그대로 쓴다. 시각이 있는 일정도 그날 오전에 알린다. `sent_reminders`로 중복을 막는다. 알림 문구는 시각이 있으면 "오늘 14:00: 제목", 없으면 "오늘: 제목"이다.
- **대상:** 이름과 연결하지 않고 구독한 기기 전체다.

## 8. 오류 처리
- 입력 검증 실패는 필드별 메시지로 보여준다(날짜 범위, 시각 범위와 30분 단위, 제목·메모 길이, 명단에 없는 번호).
- DB 장애 시 달력과 모임 화면에 오류 배너를 보여준다. 문서 뷰어는 DB를 쓰지 않으므로 영향이 없다.
- 확정할 때 모임이 이미 확정되었거나 사라졌으면 화면을 새로 불러오고 안내한다.
- 알림 발송 실패는 로그만 남긴다. 저장(모임 열림, 확정, 일정)은 알림과 무관하게 이미 끝나 있다.

## 9. 테스트 (TDD, 순수 함수부터)
- **겹침 계산:** 전원 가능, 일부만 가능, 아무도 없음, 동률 정렬, 극대 구간 합치기, 1시간 미만 구간 제외, 날짜 경계.
- **달력 월 표:** 윤년 2월, 주 시작 요일, 5주 달과 6주 달, 이전·다음 달 날짜 채우기.
- **시각 ↔ 칸 번호:** 하루 범위와 칸 크기에 따른 변환, 범위 밖 거부.
- **명단 파싱:** 정상, 중복 번호, 형식 오류, 빈 값.
- **검증:** 일정(제목·메모·시각), 모임(날짜 범위, 14일 상한, 하루 범위).
- **확정:** 참석자 계산, 이미 확정된 모임 거부, 범위 밖 거부, 트랜잭션 실패 시 아무것도 바뀌지 않음.
- **권한:** 편집 코드 없이 쓰기 거부, 가능 시간 저장은 허용, 확정된 모임의 저장은 거부.
- **알림:** 문구(시각 있음·없음), 모임당 한 번만 발송, 일정 알림 대상 선정.
- **수동 확인:** 폰에서 표 탭으로 칠하기, 데스크톱 드래그, 푸시 수신, 확정 후 달력 반영.

## 10. 확인이 필요한 값과 항목
1. 후보 날짜 최대 14일, 칸 크기 30분(고정), 하루 기본 09:00~22:00, 달력 주 시작 일요일은 제안값이다.
2. 5명 명단의 실제 이름은 나중에 `PEOPLE`만 바꾸면 된다.
3. 모임을 삭제하면 그 모임에서 만든 일정은 남는다(`meetup_id`만 비운다). 이 동작이 맞는지 확인한다.
4. 칠하기 표를 폰에서 쓸 때 탭만으로 충분한지는 구현 후 실제 폰으로 확인한다.
5. iPhone에서의 푸시는 홈 화면에 추가한 PWA에서만 동작한다(기존 스펙 6.3).

## 11. 기존 스펙에서 달라지는 점
- 일정: 종일만 → **시각(시작~종료) 선택**, 참석자·모임 연결 추가, 목록 화면(6.4) → **월 달력 화면**.
- 데이터: `events`가 확장되고 `meetups`, `availability`, `sent_notices`가 추가된다. 환경변수 `PEOPLE`이 추가된다.
- 알림: 모임 열림·확정 알림이 추가된다.
- 편집 코드로 보호하는 동작이 늘어난다(모임 만들기·삭제·확정).
